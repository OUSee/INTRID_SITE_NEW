# SEO-калькулятор — изменения от 09.09.2026

Основа: `intrid(20260909-111645).zip`. Изменены только разметка двух страниц, `js/app.js`, SCSS калькулятора и два собранных CSS. Существующие общие компоненты и backend не изменялись. Режим `mock` остается включенным.

## Переходы и разметка

- На первом шаге остается утвержденная URL-панель с чекбоксом «Сайта нет / в разработке» и дополнительными услугами.
- После анализа эта же панель остается на втором шаге. URL сохраняется, но поле и чекбокс недоступны. У существующей кнопки меняется `data-seo-calculator-action` с `analyze` на `calculate`; отдельная кнопка внизу удалена.
- На третьем шаге URL-панель скрывается. Дополнительные услуги видны только на первом шаге, их значения продолжают участвовать в расчете.
- «Проанализировать другой сайт» расположен непосредственно внутри `.container`, после `.seo-calculator__shell.card.highlighted` и вне обеих карточек результата и заявки.
- При смене этапа и явном сбросе вызывается прокрутка к корню калькулятора с учетом существующего `scroll-margin-top`; начальная инициализация не прокручивает страницу. Учитывается `prefers-reduced-motion`.

## Заявка

После успешного ответа вызывается отдельный `resetLeadForm()`: очищаются введенные контакты, select возвращается к исходному варианту, обновляются штатные nice-select и tooltip, очищается пользовательская ошибка телефона. Контекст текущего расчета в скрытых полях восстанавливается, поэтому результат и выбранные дополнительные услуги не теряются. Сообщение об успехе остается видимым. Существующая защита от повторной отправки одного и того же расчета сохранена: кнопка показывает «Отправлено», а новый расчет или полный сброс позволяют начать новый сценарий. При ошибке отправки заполненные поля не сбрасываются.

## Проверка

Синтаксис `app.js` проверен через `node --check`. Полный актуальный JS был загружен в Chromium вместе с HTML и собранными CSS каждой страницы; проверены 1440 и 390 px. Проверены переходы start → parameters → result, заблокированный URL, отсутствие нижнего блока действий, расположение reset вне карточки, прокрутка после переходов и сброса, сохранение результата, очистка контактов и select после mock-отправки, сценарий без сайта и отсутствие вызовов будущих API. Ошибок JS и горизонтального переполнения в проверенных сценариях не обнаружено.

В тестовом окружении навигация браузера к локальному серверу была заблокирована, поэтому HTML, CSS и полный `app.js` загружались непосредственно в тестовую страницу Chromium. Это не является проверкой еще не реализованных серверных API или CAPTCHA.

## Дальнейшее подключение

Существующие `fetch`-заготовки, `mock/live` транспорт, формулы Excel и контракт заявки сохранены. Backend по-прежнему должен валидировать параметры и повторно рассчитывать стоимость. Не следует включать `live` до реализации соответствующих Yii2-ручек. Дополнительную логику CAPTCHA в этой доработке не добавляли.
