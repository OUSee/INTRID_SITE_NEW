# SEO-калькулятор — упрощение верстки

Основа: intrid(20260909-064107).zip. Изменены только HTML двух страниц, SCSS компонента и собранные CSS. app.js, backend и общие компоненты не изменялись.

## Структура

seo-calculator__form
└── seo-calculator__layout (обычный двухколоночный grid)
    ├── seo-calculator__intro
    ├── seo-calculator__settings (flex-column)
    │   ├── seo-calculator__site-panel
    │   ├── seo-calculator__parameters
    │   ├── seo-calculator__extras
    └── seo-calculator__result

seo-calculator__lead располагается после основной формы и занимает всю ширину. Внутри заявки поля и кнопка остаются в одном flex-контейнере с переносом.

На первом этапе скрытые параметры, результат и действия не занимают места: слева intro, справа site-panel + extras. На втором этапе intro скрывается, слева URL-панель с заблокированным полем и кнопкой расчета, затем параметры, справа пустой результат. На третьем этапе URL-панель скрывается, а справа появляется результат. Дополнительные услуги остаются только на первом этапе. Отдельный нижний блок действий удален. Кнопка повторного анализа находится после внешней карточки, внутри общего контейнера. На ширине до 999.98px колонки становятся одной. Параметры используют штатный grid-layout--2x, который перестраивается в одну колонку до 750px.

Сохранены исходные ID, name, data-атрибуты, значения полей, тексты, ссылки и утвержденная разметка первого этапа. На втором этапе кнопка «Рассчитать» находится рядом с заблокированным URL, а не внизу панели параметров. Пустое состояние результата больше не содержит постоянно вращающееся кольцо; прелоадер остается в состоянии анализа.

## Стили

Источник: scss/components/_seo-calculator.scss. Импорт уже присутствует в scss/index.scss. Собранные css/index.css и css/index.min.css обновлены; отсутствующая в исходном архиве ссылка на css/seo-calculator.css удалена из двух страниц. Изолированные правила отвечают за компоновку и специфичные элементы результата. Готовые кнопки, карточки, tooltip, чекбоксы, селекты и прелоадер не переопределяются.

## Следующий этап

Логику анализа, расчетов, переключения состояний и отправки заявки предстоит подключить в app.js. Пока это только верстка. Существующие маршруты формы оставлены как заготовки, серверные действия не реализованы.

Для будущей логики: управлять data-state и hidden, не создавать копии полей или услуг. Селекты должны обновляться через штатный niceSelectJS. Для серверных расчетов нельзя доверять стоимости, переданной браузером.
